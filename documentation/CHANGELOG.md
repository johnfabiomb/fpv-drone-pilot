All notable changes to Venture Map are recorded here.

## [Unreleased]

### Changed
- **`supabase/bookings-schema.sql` cleaned into a canonical fresh-install script.** Folded the incremental `ALTER ADD COLUMN` migrations (§13–§17: `production_status`/`needs_production`, `task_template`, `features`, Stripe Connect columns, `deposit_*`, `invoice_details`) inline onto their `CREATE TABLE`s; completed the RESET block (now drops `booking_slots`/`tasks`/`work_items`/`invoices` too, removed legacy table drops); removed dead `DROP`s and superseded/historical comments; renumbered sections. No behaviour change — it reproduces the current live structure from scratch. (Not run against live: it begins by dropping all booking tables.)

### Fixed
- **Booking deep links no longer flash the map before loading.** Opening `/bookings` or a `/book/…` link used to bounce through `/` (the map app) via the old static `src/404.html` redirect (`location.replace('/?redirect=…')`), so the map rendered for a moment before the router jumped to the real page. `make-404.js` already generates a `404.html` that boots the SPA **in place** at the requested URL (no bounce) — the conflicting `src/404.html` (and its `angular.json` asset glob) is now removed so the bounce can't come back. `make-404.js` is the single source of `docs/404.html`. (The map app is never loaded on a booking route, so the old "hide the OAuth token from the map's Supabase client" concern is moot — the token stays on `/bookings`.) Takes effect on the next `docs/` deploy.
- **DB hardening (jm-bookings) — removed stale duplicate functions, validated the name constraint, added FK indexes.** A schema audit found old function overloads left behind by signature changes (`CREATE OR REPLACE` doesn't drop them), two of them `SECURITY DEFINER` with a mutable `search_path` — including an `anon`-callable `get_busy_ranges(start,end)`. Dropped the stale `get_busy_ranges/2`, `current_client_id/0`, two old `create_booking_request` overloads, `upsert_my_client/5`, and the orphaned `seed_production_tasks()` (its trigger was already removed). Validated `booking_has_name` (data was clean). Added covering indexes for previously unindexed foreign keys: `bookings(client_id)`, `bookings(service_id)`, `booking_links(booking_id)`, `staff_services(service_id)`. Applied live + mirrored into `bookings-schema.sql`.

### Changed
- **Bookings — all confirmations now use the in-app modal (no more browser `confirm()`).** New `ConfirmService` + a single `<app-confirm-host>` (mounted in the platform shell, mirroring the toast host) renders confirmations through the shared `<app-modal>`, so they match the booking-delete dialog's style (title, message, Cancel + a red destructive action). Replaced every native `confirm()` across the platform: Work-board card delete, invoice editor leave/reset, payment removal, booking decline + cancel/refund, and worker/service/member removal. `await confirm.ask({ title, message, confirmLabel, danger })`.
- **Bookings list — dropped the redundant "Revenue" column.** Revenue (`price_total − price_expenses`) equals Total until expense tracking exists, so the two columns were always identical; removed the column from the table (the "expected revenue" KPI stat is unchanged, and `price_revenue` stays in the data model for the future).
- **Invoice editor — "back" now returns where you came from, and won't silently discard edits.** Opening the editor from the **Invoices** list used to dump you on the *booking* on the way back (confusing); back/Cancel/save now default to the **Invoices** list, and only return to a booking when opened from one (that link passes `?from=booking`). Back/Cancel/tab-close also warn if there are unsaved changes (snapshot-based dirty check), matching the no-accidental-loss behaviour of the modals.

### Added
- **Public share links (pay link, invoice, booking) now show a proper social preview (WhatsApp/Messenger/IG/etc.).** They used to preview as a bare "johnfabiomb.com" with no image (or the map's "Explore Malta" card), because social crawlers don't run JS and the SPA fallback served the map's tags. Now: branded Open Graph/Twitter cards baked into the static HTML. The **pay link** (`/book/:token` — token in the path) gets its card from `docs/404.html`, which `make-404.js` now stamps with a "Booking · John F. Montaño" card; the **invoice** (`/book/invoice?token=…`) and **booking start** (`/book`) get dedicated static pages via `make-share-pages.js`. Shared meta rewriting in `scripts/og-meta.js`; two branded 1200×630 images (`og-invoice.png`, `og-booking.png`) generated by `scripts/gen-og-images.js`. GitHub Pages serves each file for its path (query string ignored), so the crawler reads the card while the human still boots the app. **The whole booking app is kept out of Google** (no SEO wanted yet): every booking share page is `noindex` (incl. `/book`), and `/pay/success` was removed from `prerender-routes.txt` so it's served by the `noindex` 404 fallback instead of an indexable prerendered file (`/pay` stays — it's a map page). `noindex` blocks indexing but not social crawlers, so previews still work. Cards are branded (same per type), not per-record. Add a literal-path route to `PAGES` in `make-share-pages.js` to cover more.
- **Work board — standalone cards + delete (Trello-style).** The board used to be a fixed mirror of bookings flagged `needs_production`, with no way to remove a card or add your own. It's now its own list backed by a `work_items` table: each card optionally links to a booking (carrying its client/service/date and seeding the service's task checklist) **or stands alone** (a personal to-do with just a title). **"+ New card"** creates either kind (pick a job from the dropdown, or leave it as a personal card); a **×** on each card removes it — for a booking-linked card that just takes it off the board (booking, invoice and calendar event are kept; it unflags `needs_production`), for a standalone card it deletes it. Tasks now hang off `work_item_id` (so personal cards can have checklists too); stage moves on a booking-linked card still mirror to the booking's calendar "Progress". Existing production cards were migrated 1:1. Marking a *new* booking "needs post-production" still drops a linked card on the board automatically; the board is otherwise managed by hand.
- **Bookings — Google Calendar imports now create a blocking slot + show a customer.** `sync-calendar` was inserting imported events straight into `bookings` with no `booking_slots` row, so under the multi-slot model a future import wouldn't block the worker's availability; it now also inserts a slot (same Google event id) and sets `contact_name` from the event title so the imported booking shows a customer. (Existing imports were unaffected — the migration backfilled their slots; their `contact_name` was set by a one-off data migration.)
- **Bookings — "quick name" customers (one-off bookings without a client record).** The booking form's Customer field now toggles between **Existing client** (the reusable CRM record with company/VAT — unchanged) and **Just a name** (type a one-off name, e.g. "John from Sliema"). The quick name is stored on the booking itself (`bookings.contact_name`), **never** added to the Clients table — so the CRM stays clean and there are no throwaway/orphan client rows to prune. `client_id` was already nullable; a `booking_has_name` CHECK now guarantees every booking identifies its customer (a client, a contact name, or an external import). `booking_summary.client_name` = `COALESCE(client.name, contact_name)`, so quick bookings render their name everywhere (list/detail/dashboard) with no other changes. Invoices still work: a quick booking bills to the bare name with no company/VAT (the `_invoice_bundle` RPC falls back to `contact_name`); use a real client when a VAT-ready invoice is needed. `create_booking`/`update_booking` carry `contact_name`. Fully additive.
- **Bookings — a booking can hold several time blocks (multi-slot).** One booking can now span multiple, non-contiguous time blocks across one or more days (e.g. 13:00–14:00 **and** 16:00–18:00, plus another day) instead of a single start→end span. New `booking_slots` table (org/staff/start/end per block) is the source of truth for availability and double-booking: the worker-partitioned `EXCLUDE` no-overlap constraint moved from `bookings` to `booking_slots` (`booking_slots_no_overlap`), a `slot_set_blocking()` trigger derives each slot's blocking flag from its booking status, and `get_busy_ranges` + the admin `getWorkerBusy` read slots. The booking row keeps an **envelope** (`min(start)…max(end)`) for back-compat. Atomic `create_booking`/`update_booking` RPCs insert the booking + its slots together (a losing concurrent block fails with `23P01` → "slot just taken"); `update_booking` preserves each unchanged block's Google Calendar event id (matched by exact start/end) so edits don't churn/orphan events. The admin time picker was rebuilt to manage a **list of blocks**: tap start + end to add a block, switch days and add more (added blocks persist + highlight on their own day, and are removable from a list above the calendar). Each block becomes its **own Google Calendar event** (`ensureBookingEvent` → one event per slot, titled `… (1/3)`); cancelling/deleting removes every block's event. Booking detail lists all blocks; the list shows a "+N blocks" badge (`booking_summary.slot_count`). Fully additive — existing bookings were backfilled 1 slot each.
- **Experience-centric promo — the map now promotes experiences, not providers.** Introduced an `Experience` entity (`provider → experiences[] → spots[]`): one provider offers many experiences, each appearing as its own map pin(s) at evocative spots. Tapping a pin opens `/malta/experiences/:id` (hero, gallery, the deal, and an "Offered by …" link back to the provider page). Deals resolve per experience and fall back to the provider's. The map shows experience pins (icon-only by default; photo + type badge once an experience gets a `coverImage`) **in the cluster layer**, interleaving with location pins by latitude rather than always on top. The Local Deals panel, the Browse Locations list (interleaved cards + Deals filter), and the location panel's "experiences near this spot" now list experiences via a shared `ExperienceCardComponent`; the map shows experience pins (never provider pins) on every promo surface — provider pins remain only for the Groups feature; the coupon box was extracted into a shared `DealBoxComponent` reused by provider **and** experience detail. Seeded 12 experiences across Santa Maria, Yippee and Block with draft pin coordinates (to be fine-tuned). All gated by `FEATURES.PROMOTIONS`. See `documentation/EXPERIENCES.md`. Provider/brand pages and the nav-interstitial ads are unchanged.
- **Yippee experiences enriched from official brochures.** Rewrote all six Yippee experiences with first-party detail (durations, prices incl. child/infant rates, 21+ self-drive rules, all-inclusive list, full itineraries, seasonality) and added the brochure flyers as gallery images. Renamed the placeholder `yippee-sunset-cruise` → `yippee-round-gozo-cruise` to match the real catalogue (half-day Blue Lagoon cruise + full-day Round Gozo cruise; land sunset variants folded into each tour's description).
- **New location — Il-Kalanka (id 75).** Hidden swimming bay on the Delimara peninsula (Marsaxlokk), south-east Malta, near St Peter's Pool. Added to `locations.json` with three photos, prerender route, and sitemap entry. Distinct from the existing Ta' Kalanka Sea Cave (id 49).

### Added

The standalone **Hours field is gone**: charges (pricing) and the calendar **span are decoupled** — per-line hours only feed the invoice description/price, while the booking's start/finish is set by **tapping a start and end on the calendar** (the picker is now Calendly-style range selection; editing prefills the existing span, and not touching it preserves the original duration). Creating a **new client** from the booking form now opens the **same full client editor** (name + email/phone/company/**VAT**/billing address/notes) as the Clients page, then refreshes the list and **auto-selects** the new client — no more half-empty client stubs. The line-items + client editors are extracted into reusable components (`booking/ui/line-items-editor/`, `booking/ui/client-editor/`) used across the booking form, invoice editor and Clients page. `needs_production` flag added (a booking joins the Work board only when ticked; external calendar events never do). Removed the now-dead service dropdown, inline new-client fields and segmented toggle.

Services are no longer a mandatory dropdown — they're an optional **"add a line from a service"** helper that pre-fills a line's description + price (for the chosen hours) and stays editable; the worker is any bookable staff. The breakdown is saved to the `invoices` table on create/edit, so the invoice is **ready immediately**. Conversely, **editing an invoice now updates the booking's total** (and its calendar event) — the line items are the single source of truth (previously invoice edits were decoupled from the booking). The booking **detail page shows a "What's billed" breakdown** + Edit-invoice link. Built on a reusable **`LineItemsEditorComponent`** (`booking/ui/line-items-editor/`) shared by the booking form *and* the invoice editor (zero duplication), and reuses the existing `invoices.line_items` column — **no new tables**. The client/company/VAT still come through the `client_id` relation, never duplicated.
- **Clients — add & edit (incl. billing details for invoices).** The Clients screen was read-only; it now has a **New client** button and every row opens an **edit modal** (name + optional email, phone, company, **VAT number**, **billing address**, internal notes). Saved via `BookingDataService.saveClient()` (insert or update; org-admin RLS already allowed it). Billing fields are optional but, once filled, flow straight onto that client's invoices — which reference the client by **`client_id` relation** (the `invoices` table stores only line items / notes / issue date; client + company details are never duplicated there). The list gained a **VAT** column.
- **Bookings & Invoices — professional tabbed organization + next-first ordering.** The **Bookings** list now opens on an **Upcoming** tab with your **next booking pinned at the top** (and a "NEXT" highlight) — previously it showed the furthest-out booking first. Tabs (each with a live count): **Upcoming · Pending · Unpaid · Paid · Past · External · Cancelled · All**, plus a **search** box (ref / client / job). Imported Google events get their own **External** tab and are kept out of Upcoming/Past so the schedule shows only real jobs. Every tab is **strictly chronological** (forward-looking tabs soonest→latest; history most-recent→oldest — no mixed ordering). **Upcoming** includes everything from **today onward — real and imported (external) events** — so today's and synced calendar items show alongside jobs. The date column shows a friendly relative hint ("Tomorrow", "in 3 days"), and cash requests live under the **Pending** tab (count badge in red). **Invoices** gained matching payment-status tabs — **All · Unpaid · Partially paid · Paid** (with counts) on top of the existing year filter — a per-row status badge, and newest-first ordering; the summary totals reflect the whole selected period.
- **Bookings — imported Google events can be enriched into real bookings, and admin edits sync back to Google.** Imported (external) calendar events now have an **"Edit / enrich"** action in the bookings list; opening one in the form lets you add a client, price, description, change the title/time/location, and Save — at which point it **becomes a normal booking** (`is_external` cleared → the "External" badge becomes Unpaid, counts in revenue, invoiceable) and — when card payment is enabled — **saving now hands you a payment link to send** (the edit flow previously returned to the list with no link). Crucially, **saving any booking edit now pushes to Google Calendar** (previously only payment/amount changes did): the event's **title, time, location and description** are all updated (before, `ensureBookingEvent` patched the description only, and the edit path didn't sync at all). The calendar description now leads with your **free-text Description**, followed by the auto summary (Client / Total / Payment / Ref). `updateCalendarEvent` extended to patch start/end; `sync-booking-event` + the other event-writing functions redeployed. **Note:** this is one-way (app → Google) — edits made directly in Google Calendar don't flow back (the "Sync" pull only imports brand-new events).
